# Локализация интерфейса

Весь человекочитаемый текст UI живёт в одном файле — `src/i18n/locale.yaml`. Никакой рантайм-смены языка и никакой поддержки нескольких локалей одновременно: язык фиксируется один раз при настройке инстанса, администратор форка правит файл напрямую.

## Почему банк имён не локализуется

Имена вроде «Куберслав» и их hint'ы — это словообразование, завязанное конкретно на русское имя «Святослав». Дословный перевод бессмысленен: в другом языке нет аналогичной игры слов с тем же именем. Поэтому для форка на другом языке предполагается не перевод существующего банка, а написание **нового** банка с нуля — этот случай уже полностью покрыт форматом из [`01-name-bank.md`](./01-name-bank.md), никакой отдельной инфраструктуры локализации ему не нужно.

По той же причине текст внутри самих OG-шаблонов (см. [`06-og-rendering.md`](./06-og-rendering.md)) тоже не подчиняется `locale.yaml` — адаптация конкретного шаблона остаётся на ответственности того, кто форкает проект под себя.

## Формат `locale.yaml`

```yaml
locale_code: ru-RU        # BCP 47, используется Intl.DateTimeFormat для дат
date_style: long          # full | long | medium | short

meta:
  site_title: "СвятБелоз — рулетка имён"
  og_description: "Сегодня ты — {{name}}"

home:
  eyebrow: "сегодня ты —"
  share_button: "Поделиться"
  reroll_hint: "Перезагрузка результата — в полночь"

share_page:
  heading: "{{date}}: {{name}}"
  fallback_heading: "Этот Святослав потерян во времени"
```

`{{name}}`/`{{date}}` — плейсхолдеры, подставляются простой функцией `interpolate()` в `src/i18n/loader.ts` (`.replace(/\{\{(\w+)\}\}/g, ...)`), без сторонних i18n-библиотек. Даты форматируются через встроенный `Intl.DateTimeFormat(locale_code, { dateStyle })` — не нужно вручную хранить переводы названий месяцев под каждый язык.

## Валидация

При старте сервера `loadLocale()` парсит файл через Zod-схему, где **все** ключи обязательны. Не хватает ключа или он пустой — сервис не стартует, ошибка указывает точный путь до проблемного ключа (например, `home.share_button`), а не просто "локаль невалидна". Дополнительно проверяется, что `locale_code` — валидный BCP 47 тег: конструктор `Intl.DateTimeFormat` бросает `RangeError` на мусорное значение, эта ошибка превращается в понятное сообщение.

`src/i18n/locale.example-en.yaml` — справочный пример перевода на английский для форкеров; в коде он не используется, только `locale.yaml` активен.

## Доступ из кода

Бэкенд импортирует загруженный объект локали напрямую (общий процесс с рендерером OG-картинок). Фронтенд получает его через `GET /api/locale.json` — один fetch при загрузке страницы.
