# Клиентский фингерпринт

Личное «имя дня» вычисляется полностью в браузере, без единого сетевого запроса, несущего данные о браузере. Это не деталь реализации, а сознательный выбор в пользу прозрачности — открыть DevTools → Network и увидеть, что ничего не улетает, проще, чем поверить на слово.

## Какие сигналы собираются

Фиксированный реестр в `public/assets/fingerprint.js` — это всё, что вообще доступно через стандартные браузерные API, без канвас/WebGL-фингерпринтинга (тот тоже сознательно не используется — ради той же прозрачности):

| Сигнал | Источник |
|---|---|
| `language` | `navigator.language` |
| `timezone` | `Intl.DateTimeFormat().resolvedOptions().timeZone` |
| `screenResolution` | `screen.width` × `screen.height` |
| `hardwareConcurrency` | `navigator.hardwareConcurrency` |
| `userAgent` | `navigator.userAgent` |

Все эти значения браузер и так раскрывает явно (например, `User-Agent`) или отдаёт без специальных разрешений — ничего из этого не логируется и не сохраняется, вычисление полностью эфемерно.

## Что из этого реально используется — решает сервер

Какое подмножество сигналов и в каком порядке участвует в сиде — задаётся не в коде фронтенда, а через `GET /api/config.json` → `fingerprintFields` (переменная окружения `FINGERPRINT_FIELDS`, по умолчанию — все пять). Если понадобится убрать сигнал (скажем, окажется, что браузеры всё активнее режут `hardwareConcurrency`) или добавить новый — это смена переменной окружения и рестарт контейнера, без передеплоя статики.

Сервер валидирует `FINGERPRINT_FIELDS` при старте против собственного списка допустимых имён (`KNOWN_FINGERPRINT_FIELDS` в `src/config/fingerprintFields.ts`) — опечатка в конфиге не даёт сервису запуститься. На клиенте поведение мягче: неизвестное имя сигнала (например, версии бэкенда и фронтенда разъехались) просто пропускается с `console.warn`, не ломая страницу для всех.

## Соль

`fingerprintSalt` тоже приходит с сервера через `/api/config.json` (env `FINGERPRINT_SALT`), а не хардкодится во фронтенде. Секретности в этом нет — алгоритм и так виден в исходниках, а теперь и ответ эндпоинта виден в Network. Смысл соли в другом: развести неймспейсы сидов «имени дня» и «личного имени», и дать простой рычаг «перемешать все результаты разом» — смена одной переменной окружения.

## Формула сида

```js
// public/assets/fingerprint.js
function buildSeed(date, fingerprintFields, salt) {
  const collected = fingerprintFields.map(collectSignal).filter(v => v !== null);
  return [date, ...collected, salt].join("|");
}
```

Дата всегда первым элементом, соль — последним; конфигурируется только средняя часть. Дальше — `crypto.subtle.digest("SHA-256", ...)` (нативный Web Crypto API, никаких сторонних библиотек) и та же математика `seedToFloats`/`pickWeighted`/`pickEqual`, что и на сервере, — реализованная отдельно в `public/assets/selectorMath.js` (см. [`02-selector.md`](./02-selector.md) про то, зачем эта логика продублирована, а не вынесена в общий модуль).

## Откуда браузер берёт данные банка

`GET /api/name-bank.json` отдаёт только `regular`-категории — служебная `not_found` клиенту не видна и не нужна: fallback для битых ссылок целиком обрабатывается на сервере, см. [`03-share-link.md`](./03-share-link.md). Ответ строится один раз при старте сервера и кэшируется агрессивно — банк не меняется без рестарта.

## Весь путь на главной странице

`public/assets/script.js` делает это по шагам: параллельно запрашивает `config.json`, `name-bank.json`, `locale.json` → собирает сигналы согласно конфигу → строит сид → считает SHA-256 → получает два float'а → выбирает категорию и имя → показывает результат → по клику на «Поделиться» тут же в браузере собирает токен (`base64url(entry.id + ":" + Date.now())`) — без обращения к серверу.
