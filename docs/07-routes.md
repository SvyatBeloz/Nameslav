# HTTP-эндпоинты

| Метод | Путь | Что делает | Кэш |
|---|---|---|---|
| `GET` | `/` | Главная страница — статика, вся персонализация происходит в браузере | обычное браузерное кэширование статики |
| `GET` | `/assets/*` | Статика фронтенда (CSS, JS, шрифты) | обычное браузерное кэширование статики |
| `GET` | `/og-image.png` | Картинка «имени дня», одна на всех в течение суток | диск, раз в сутки |
| `GET` | `/r/:token` | Страница share-ссылки с персональными OG-метатегами | не кэшируется |
| `GET` | `/r/:token/og-image.png` | Картинка для конкретной share-ссылки | не кэшируется — разовое событие |
| `GET` | `/api/name-bank.json` | `regular`-категории банка имён — нужны браузеру для выбора личного имени | агрессивно, из памяти |
| `GET` | `/api/locale.json` | Тексты интерфейса | агрессивно, из памяти |
| `GET` | `/api/config.json` | `fingerprintSalt`, `fingerprintFields`, `siteDomain`, `configVersion` | агрессивно, из памяти |
| `GET` | `/livez` | Liveness — процесс жив и отвечает на HTTP | не кэшируется |
| `GET` | `/readyz` | Readiness — готовность принимать трафик | не кэшируется |

`GET /` и `GET /assets/*` не имеют отдельных обработчиков — отдаются напрямую через `express.static`, настроенный в `src/server.ts`.

## Liveness и readiness — зачем раздельно

`GET /livez` отвечает `200` сразу же, как только Express способен обработать запрос — не проверяет ни банк, ни локаль, ни диск. Это намеренно: liveness должен ловить только «процесс фундаментально завис», а не временные проблемы с зависимостями — иначе получаем бессмысленные перезапуски вместо решения настоящей проблемы.

`GET /readyz` (`src/routes/health.ts`) отвечает `200`, только если банк имён загружен и непуст, локаль загружена, и директория кэша существует и доступна на запись. При провале — `503` с JSON, где явно указано, какая именно проверка не прошла:

```json
{ "status": "not_ready", "checks": { "bankLoaded": true, "localeLoaded": true, "cacheWritable": false } }
```

Поскольку банк и локаль загружаются синхронно ещё до того, как сервер начинает слушать порт (невалидные — сервис вообще не стартует), первые две проверки на практике всегда истинны после успешного запуска; реальную пользу readiness даёт в основном проверка диска.

## Чего здесь нет — и почему

- **Отдельного эндпоинта для фингерпринта** — не нужен, вычисление личного имени целиком происходит в браузере, см. [`05-fingerprint.md`](./05-fingerprint.md).
- **Write/CRUD-эндпоинтов** — добавление имён через API, статистика и подобное не входят в текущий объём.
- **Смены локали на лету** — локаль статична на инстанс, см. [`04-i18n.md`](./04-i18n.md).
