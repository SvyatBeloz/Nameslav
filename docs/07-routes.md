# HTTP-эндпоинты

| Метод | Путь | Что делает | Кэш |
|---|---|---|---|
| `GET` | `/` | Главная страница: сервер заполняет шаблон `templates/index.html`, персонализация происходит в браузере | `no-cache` + ETag (ревалидация) |
| `GET` | `/index.html` | 301 на `/` — единственная каноническая точка | не кэшируется |
| `GET` | `/assets/*` | Статика фронтенда (CSS и JS) | обычное браузерное кэширование статики |
| `GET` | `/robots.txt` | Разрешает обход целиком — см. ниже | статика |
| `GET` | `/og-image.png` | Статическая карточка-превью сервиса (не зависит от даты) | в памяти, один рендер на процесс |
| `GET` | `/r/:token` | Страница share-ссылки с персональными OG-метатегами | `no-cache` + ETag (ревалидация) |
| `GET` | `/r/:token/og-image.png` | Картинка для конкретной share-ссылки | `immutable` для валидного токена, час для фоллбэка — см. [`03-share-link.md`](./03-share-link.md) |
| `GET` | `/api/name-bank.json` | `regular`-категории банка имён — нужны браузеру для выбора личного имени | `no-cache` + ETag (ревалидация), из памяти |
| `GET` | `/api/locale.json` | Тексты интерфейса | `no-cache` + ETag (ревалидация), из памяти |
| `GET` | `/api/config.json` | `fingerprintSalt`, `fingerprintFields`, `siteDomain`, `configVersion` | `no-cache` + ETag (ревалидация), из памяти |
| `GET` | `/livez` | Liveness — процесс жив и отвечает на HTTP | не кэшируется |
| `GET` | `/readyz` | Readiness — готовность принимать трафик | не кэшируется |

## Шаблоны страниц

`/` и `/r/:token` рендерятся из HTML-шаблонов в `templates/` — `index.html` и `share.html`. Оба заполняются одной функцией `renderTemplate()` (`src/utils/template.ts`), которая экранирует **каждое** значение: ни в одном шаблоне нет слота, принимающего разметку, — именно это делает безопасной подстановку данных из запроса на share-странице. Функция строга в обе стороны: незаполненный плейсхолдер и переданное значение без плейсхолдера одинаково приводят к ошибке, чтобы опечатка не уехала к посетителю в виде литерального `{{HINT}}`.

Шаблоны лежат **не** в `public/`. Иначе `express.static` отдавал бы их как обычные файлы — с плейсхолдерами наружу; раньше это лечилось флагом `index: false` и редиректом с `/index.html`, но появление второго шаблона сделало бы дыру снова. Теперь веб-корень содержит только то, что действительно должно отдаваться как есть: `assets/*.js`, `style.css`, `favicon.ico`, `robots.txt`. Шрифты для OG тоже переехали (`assets/fonts/`, см. [`06-og-rendering.md`](./06-og-rendering.md)) — браузеру они не нужны, а весили 1.2 МБ публичной статики.

Главная и share-страница описывают одну и ту же карточку, и это осознанно оставленное дублирование: свести их в один шаблон можно было бы только механизмом партиалов, которого в проекте без шага сборки нет. Файлы лежат рядом и почти построчно параллельны, в шапке каждого — ссылка на соседний.

## Liveness и readiness — зачем раздельно

`GET /livez` отвечает `200` сразу же, как только Express способен обработать запрос — не проверяет ни банк, ни локаль, ни диск. Это намеренно: liveness должен ловить только «процесс фундаментально завис», а не временные проблемы с зависимостями — иначе получаем бессмысленные перезапуски вместо решения настоящей проблемы.

`GET /readyz` (`src/routes/health.ts`) отвечает `200`, только если банк имён загружен и содержит хотя бы одну `regular`-категорию, и локаль загружена. При провале — `503` с JSON, где явно указано, какая именно проверка не прошла:

```json
{ "status": "not_ready", "checks": { "bankLoaded": false, "localeLoaded": true } }
```

Поскольку банк и локаль загружаются синхронно ещё до того, как сервер начинает слушать порт (невалидные — сервис вообще не стартует), обе проверки на практике всегда истинны после успешного запуска; они оставлены, чтобы эндпоинт документировал, что значит «готов» для этого сервиса. Дисковой кэш OG-картинок убран (см. [`06-og-rendering.md`](./06-og-rendering.md)), поэтому проверки записи диска в readiness больше нет.

## Заголовки безопасности

`src/routes/security.ts` монтируется первым в `src/app.ts`, до всех роутеров — чтобы заголовки попадали и на статику, и на JSON, и на картинки, и на страницы ошибок, а не только туда, где о них вспомнили. Плюс `app.disable("x-powered-by")`: версия фреймворка наружу не нужна.

CSP построен от `default-src 'none'`, каждое послабление осознанное:

| Директива | Зачем |
|---|---|
| `script-src 'self'` | Только свои файлы из `/assets`. **Без** `'unsafe-inline'` — ради этого инлайновый скрипт со share-страницы вынесен в `/assets/tilt.js` |
| `style-src 'self' 'unsafe-inline'` | `style.css` плюс инлайновые `style`-атрибуты: share-страница передаёт акцентный оттенок как `style="--hue: N"`, а `script.js` пишет в `.style`. Точнее было бы `style-src-attr`, но Firefox эту директиву не реализует и откатится на `style-src`, молча погасив акцент |
| `img-src` / `font-src` / `connect-src 'self'` | Фавикон и OG-картинки, свои шрифты, три fetch'а к `/api/*.json` |
| `base-uri` / `form-action` / `frame-ancestors 'none'` | `<base>` и форм на сайте нет, и встраиваться в чужой фрейм ему незачем |

Дополнительно: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` (в тон отказу от сбора данных), `X-Frame-Options: DENY` как легаси-дублёр `frame-ancestors`, `Cross-Origin-Opener-Policy: same-origin`.

`Strict-Transport-Security` намеренно не отправляется: TLS терминируется перед процессом, сам контейнер говорит по обычному HTTP и не может знать, пришёл ли запрос по HTTPS. HSTS — дело того, кто терминирует TLS.

## robots.txt и индексация

`/r/:token` в `robots.txt` **не** запрещён, и это принципиально: превью-краулеры, ради которых share-ссылки и существуют (`facebookexternalhit`, `Twitterbot`, `LinkedInBot`), уважают `robots.txt` — запрет пути убил бы ровно ту фичу, которую он должен был защитить. Вместо этого сама страница несёт `<meta name="robots" content="noindex">`: краулер её отрисует, поисковик не станет индексировать бесконечное множество одноразовых URL.

## Ошибки: 404 и 500

Обе терминальные ручки живут в `src/routes/errors.ts` и монтируются последними, уже после всех роутеров (`src/app.ts`):

- **404** — путь, который не забрал ни один роутер. Отдаётся своя страница на языке локали (`errors.not_found_title` / `errors.not_found_text`, см. [`04-i18n.md`](./04-i18n.md)), а не дефолтная английская `Cannot GET /x` от Express.
- **500** — всё, что бросил любой роут. Реальная ошибка пишется в stderr, наружу уходит только общая формулировка. Дефолтный обработчик Express вместо этого вкладывает `err.stack` прямо в тело ответа, если `NODE_ENV` не равен ровно `production` — то есть при запуске образа без переменной окружения наружу утекали абсолютные пути сервера. Свой обработчик не зависит от `NODE_ENV` вообще (образ всё равно задаёт его сам, см. [`08-deployment.md`](./08-deployment.md)).

Под `/api/*` обе ручки отвечают JSON (`{"error": "not_found"}` / `{"error": "internal_server_error"}`), а не HTML-страницей.

## Чего здесь нет — и почему

- **Отдельного эндпоинта для фингерпринта** — не нужен, вычисление личного имени целиком происходит в браузере, см. [`05-fingerprint.md`](./05-fingerprint.md).
- **Write/CRUD-эндпоинтов** — добавление имён через API, статистика и подобное не входят в текущий объём.
- **Смены локали на лету** — локаль статична на инстанс, см. [`04-i18n.md`](./04-i18n.md).
