# Неймосламова рулетка

## Зачем это существует

Коллеги автора регулярно коверкают его имя «Святослав» в шутливые составные варианты по схеме «[контекст]ослав» — Куберслав, Девопсослав, Домослав и так далее. Этот проект превращает бытовую шутку в маленький сайт: каждый посетитель `name.svyatbeloz.link` ежедневно получает своего персонального «Святослава дня» — детерминированно, без регистрации и без хранения каких-либо данных о посетителе.

Аудитория — прежде всего коллеги автора, но сайт устроен так, чтобы быть понятным и забавным и случайному постороннему человеку.

## Как это устроено

Здесь два параллельных механизма выбора имени, и оба детерминированы:

- **Личное имя.** При заходе на главную страницу браузер сам, без единого сетевого запроса, вычисляет «имя дня» — хэширует текущую дату вместе с несколькими безобидными техническими характеристиками (язык интерфейса, часовой пояс, разрешение экрана и т.п.). Один и тот же человек в течение суток видит одно и то же имя, на следующий день — другое. Это сознательный архитектурный выбор в пользу прозрачности: любой может открыть вкладку Network и убедиться, что ничего никуда не отправляется.
- **Имя дня.** Для самого корня сайта — общее для всех, вычисляется на сервере по одной только дате. Оно показывается, когда ссылку на сайт (не персональную) кидают в чат и краулер мессенджера запрашивает превью.

Результатом можно поделиться: ссылка `/r/:token` кодирует сам результат (не сид, из которого он получен), поэтому у любого, кто её откроет — включая краулера соцсети, — отрисуется именно тот же результат, без базы данных на сервере.

## Стек

| Компонент | Технология |
|---|---|
| Бэкенд | Node.js, TypeScript, Express |
| OG-картинки | [Takumi](https://takumi.kane.tw/) — рендерит JSX/HTML прямо в PNG, без headless-браузера |
| Данные | YAML (банк имён, тексты интерфейса), валидируются через Zod при старте |
| Фронтенд | Vanilla JS/HTML/CSS, без фреймворков и шага сборки |
| Контейнеризация | Docker / docker-compose, архитектура совместима с Kubernetes на будущее |

## Архитектурные принципы

- **Ничего не хранится.** Ни данные браузера, ни история выпавших имён. Единственное исключение — картинка «имени дня» кэшируется на диск на сутки, просто чтобы не перерендеривать одно и то же изображение на каждый запрос.
- **Персонализация — целиком клиентская.** Сервер даже не участвует в вычислении личного имени: он только отдаёт read-only JSON-данные (банк имён, тексты, конфигурацию), из которых браузер сам всё считает.
- **Бэкенд минимальный, но настоящий.** Он нужен для двух вещей: рендер OG-картинок (это требование самого механизма Open Graph — превью для соцсетей не может родиться в браузере того, кто ссылку ещё не открыл) и отдача тех самых read-only JSON-данных.
- **Проект рассчитан на форк.** Банк имён, тексты интерфейса, домен, состав хэшируемых сигналов — всё вынесено в YAML/переменные окружения. Чтобы сделать свою версию с другой игрой слов, достаточно написать свой банк имён — трогать код не нужно.
