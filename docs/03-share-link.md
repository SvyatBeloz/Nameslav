# Ссылки шаринга

Идея: дать пользователю поделиться своим результатом так, чтобы у любого, кто откроет ссылку — включая краулера соцсети, прогревающего OG-превью, — отрисовался именно тот же результат, без базы данных на сервере.

## Почему в токене не хэш

Хэш — одностороннее преобразование: из него нельзя восстановить исходное имя без отдельного хранилища соответствий. Раз хранить ничего нельзя, ссылка кодирует сам **результат** — точнее, стабильный `id` записи из банка имён, — а не сид, из которого он был вычислен.

## Формат токена

```
payload = "<id>:<unixTimestampMs>"
token   = base64url(payload)
url     = https://name.svyatbeloz.link/r/<token>
```

`id` — идентификатор конкретной записи имени. `unixTimestampMs` (в миллисекундах, как отдаёт `Date.now()`) нужен только чтобы показать корректную дату на странице шаринга («21 июня 2026: Куберслав» вместо «сегодня ты —», что было бы неверно при просмотре ссылки спустя время) — на валидность токена он не влияет.

Токен собирается прямо в браузере в момент клика на «Поделиться», без обращения к серверу.

## Обработка на сервере (`src/routes/share.ts`)

```
GET /r/:token               → HTML со страницей + OG-метатегами
GET /r/:token/og-image.png  → сама картинка, тот же рендерер, что и /og-image.png
```

Любая ошибка на пути декодирования — битый base64, отсутствующий разделитель, `id`, которого нет в банке (например, категорию удалили после того, как ссылка была отправлена), — приводит к одному и тому же фоллбэку: случайной записи из служебной категории `role: not_found`. Никакого явного 404 — посетитель увидит шутливую заглушку («Этот Святослав потерян во времени») вместо технической ошибки.

## Кэширование

На диск не кэшируется ничего. Статическая карточка корня (`/og-image.png`) мемоизирована в памяти процесса — один рендер, результат одинаков для всех, см. [`06-og-rendering.md`](./06-og-rendering.md). Картинки для share-ссылок **не кэшируются вообще**: каждая ссылка — разовое, уникальное для конкретного пользователя и момента событие; закэшированный результат всё равно нельзя переиспользовать между разными токенами, даже с одинаковым `id` (у каждого свой `timestamp`). Именно поэтому `timestamp` можно безопасно выводить прямо на картинке — конфликтов кэш-ключей тут просто не возникает, потому что кэша нет.
