# Банк имён

Банк имён — источник данных для выбора «Святослава дня»: набор YAML-файлов в `src/names/bank/`, по одному файлу на категорию. Загружается и валидируется один раз при старте сервера (`src/names/bankLoader.ts`), дальше живёт в памяти — никаких обращений к диску на каждый запрос.

## Формат файла категории

```yaml
category:
  slug: devops
  title: Девопс
  version: 1
  template: whoami
  weight: 10
  role: regular

names:
  - id: kuberslav
    name: Куберслав
    hint: сегодня что-то сломается само, и чинить будешь ты
  - id: devopsoslav
    name: Девопсослав
    hint: день, когда "works on my machine" звучит особенно фальшиво
```

| Поле | Описание |
|---|---|
| `slug` | Внутреннее имя категории на латинице, используется как тег |
| `title` | Человекочитаемое название на кириллице |
| `version` | Версия формата записи — задел на будущие миграции |
| `template` | Какой OG-шаблон использовать (см. [`06-og-rendering.md`](./06-og-rendering.md)) |
| `weight` | Вес категории при случайном выборе (см. [`02-selector.md`](./02-selector.md)) |
| `role` | `regular` для обычных категорий или одна из технических ролей ниже |
| `names[].id` | Стабильный идентификатор записи, не меняется при правке имени/hint'а — используется в share-ссылках |
| `names[].name` | Само имя-вариация |
| `names[].hint` | Шутливая расшифровка |

Имя файла не имеет значения — `slug` объявляется явно внутри файла.

## Технические роли

Помимо `regular`-категорий, участвующих в обычной ротации, есть служебная роль:

| Роль | Назначение |
|---|---|
| `not_found` | Категория-заглушка для битых или несуществующих ссылок шаринга. Исключена из обычной ротации, должна содержать несколько имён — при попадании сюда выбор внутри категории случайный, см. [`03-share-link.md`](./03-share-link.md) |

Список допустимых `template` и `role` — не магические строки в YAML, а типизированные реестры в коде (`TEMPLATE_IDS` в `src/og/templates/registry.ts`, `ROLE_IDS` в `src/names/roles.ts`), на которых построены Zod-enum'ы. Если YAML ссылается на несуществующий шаблон или роль — сервис не запустится.

## Валидация

`src/names/bankValidator.ts` проверяет то, что одна Zod-схема на файл проверить не может — консистентность между файлами:

- глобальная уникальность `id` и `name` по всему банку;
- уникальность `slug` категории;
- не больше одной категории на каждую техническую роль (`regular` не ограничена);
- (предупреждение, не блокирует старт) пустая категория или `name`/`hint` подозрительной длины.

При нарушении любой обязательной проверки сервер не стартует — ошибка называет конкретный файл и запись, а не просто "что-то не так с банком".

## Текущее содержимое

`src/names/bank/` сейчас содержит стартовый набор — `devops.yaml`, `byt.yaml` и служебный `not-found.yaml` — этого достаточно, чтобы всё работало и было видно, как устроена ротация. Расширение банка новыми категориями и именами не требует изменений в коде: достаточно добавить `*.yaml`-файл по этому формату.
