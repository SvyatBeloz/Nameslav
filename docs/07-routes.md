# HTTP-эндпоинты

| Метод | Путь | Что делает | Кэш |
|---|---|---|---|
| `GET` | `/` | Главная страница: сервер подставляет абсолютные OG-метатеги в `index.html`, персонализация происходит в браузере | `no-cache` + ETag (ревалидация) |
| `GET` | `/index.html` | 301 на `/` — единственная каноническая точка | не кэшируется |
| `GET` | `/assets/*` | Статика фронтенда (CSS, JS, шрифты) | обычное браузерное кэширование статики |
| `GET` | `/og-image.png` | Статическая карточка-превью сервиса (не зависит от даты) | в памяти, один рендер на процесс |
| `GET` | `/r/:token` | Страница share-ссылки с персональными OG-метатегами | `no-cache` + ETag (ревалидация) |
| `GET` | `/r/:token/og-image.png` | Картинка для конкретной share-ссылки | `immutable` для валидного токена, час для фоллбэка — см. [`03-share-link.md`](./03-share-link.md) |
| `GET` | `/api/name-bank.json` | `regular`-категории банка имён — нужны браузеру для выбора личного имени | `no-cache` + ETag (ревалидация), из памяти |
| `GET` | `/api/locale.json` | Тексты интерфейса | `no-cache` + ETag (ревалидация), из памяти |
| `GET` | `/api/config.json` | `fingerprintSalt`, `fingerprintFields`, `siteDomain`, `configVersion` | `no-cache` + ETag (ревалидация), из памяти |
| `GET` | `/livez` | Liveness — процесс жив и отвечает на HTTP | не кэшируется |
| `GET` | `/readyz` | Readiness — готовность принимать трафик | не кэшируется |

`GET /` обрабатывает home-роут (`src/routes/home.ts`): он подставляет в шаблон `public/index.html` абсолютные OG-метатеги, см. [`06-og-rendering.md`](./06-og-rendering.md). `GET /assets/*` отдаётся напрямую через `express.static` (с `index: false`, чтобы статика не конкурировала с home-роутом за `/`).

## Liveness и readiness — зачем раздельно

`GET /livez` отвечает `200` сразу же, как только Express способен обработать запрос — не проверяет ни банк, ни локаль, ни диск. Это намеренно: liveness должен ловить только «процесс фундаментально завис», а не временные проблемы с зависимостями — иначе получаем бессмысленные перезапуски вместо решения настоящей проблемы.

`GET /readyz` (`src/routes/health.ts`) отвечает `200`, только если банк имён загружен и содержит хотя бы одну `regular`-категорию, и локаль загружена. При провале — `503` с JSON, где явно указано, какая именно проверка не прошла:

```json
{ "status": "not_ready", "checks": { "bankLoaded": false, "localeLoaded": true } }
```

Поскольку банк и локаль загружаются синхронно ещё до того, как сервер начинает слушать порт (невалидные — сервис вообще не стартует), обе проверки на практике всегда истинны после успешного запуска; они оставлены, чтобы эндпоинт документировал, что значит «готов» для этого сервиса. Дисковой кэш OG-картинок убран (см. [`06-og-rendering.md`](./06-og-rendering.md)), поэтому проверки записи диска в readiness больше нет.

## Ошибки: 404 и 500

Обе терминальные ручки живут в `src/routes/errors.ts` и монтируются последними, уже после всех роутеров (`src/app.ts`):

- **404** — путь, который не забрал ни один роутер. Отдаётся своя страница на языке локали (`errors.not_found_title` / `errors.not_found_text`, см. [`04-i18n.md`](./04-i18n.md)), а не дефолтная английская `Cannot GET /x` от Express.
- **500** — всё, что бросил любой роут. Реальная ошибка пишется в stderr, наружу уходит только общая формулировка. Дефолтный обработчик Express вместо этого вкладывает `err.stack` прямо в тело ответа, если `NODE_ENV` не равен ровно `production` — то есть при запуске образа без переменной окружения наружу утекали абсолютные пути сервера. Свой обработчик не зависит от `NODE_ENV` вообще (образ всё равно задаёт его сам, см. [`08-deployment.md`](./08-deployment.md)).

Под `/api/*` обе ручки отвечают JSON (`{"error": "not_found"}` / `{"error": "internal_server_error"}`), а не HTML-страницей.

## Чего здесь нет — и почему

- **Отдельного эндпоинта для фингерпринта** — не нужен, вычисление личного имени целиком происходит в браузере, см. [`05-fingerprint.md`](./05-fingerprint.md).
- **Write/CRUD-эндпоинтов** — добавление имён через API, статистика и подобное не входят в текущий объём.
- **Смены локали на лету** — локаль статична на инстанс, см. [`04-i18n.md`](./04-i18n.md).
